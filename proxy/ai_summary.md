## semantic_overview
- The codebase implements an OpenAI-compatible FastAPI web server (`proxy/app/main.py`).
- It translates standard OpenAI `/v1/chat/completions` requests into native ChatGPT web client commands using the underlying `transport_runtime.py` and `wrapper/chatgpt.py`.
- It supports advanced automation flows via `playwright`, authenticated sessions, and headless/non-headless browser management.
- It includes a specialized `tools_shim` module which enables tool-calling / function-calling compatibility specifically tuned for the `pi` coding agent.

## top_level_entrypoints
- `make start-proxy`: Starts the uvicorn server on `127.0.0.1:8081` (formerly 8080).
- `proxy/app/main.py`: The FastAPI application definition and exception handling.
- `proxy/app/router.py`: The API routing for `/health`, `/v1/models`, and `/v1/chat/completions`.

## external_behavior
### input
- Accepts standard OpenAI JSON payloads for chat completions.
- `model`: Maps virtual model strings like `chatgpt-playwright` and `chatgpt-authenticated` to internal transport modes.
- `messages`: Standard OpenAI message history.
- `tools` (optional): Standard OpenAI tool-calling schemas.
- `stream` (optional): Standard OpenAI boolean for Server-Sent Events (SSE) streaming.

### output
- Returns OpenAI-shaped JSON responses (`chatcmpl-***`).
- Generates OpenAI-compliant streaming chunks (`data: {...}\n\n`) mapping the native ChatGPT text-stream into granular delta streams.
- Translates `pi` agent tool invocations from text-based representations into standard OpenAI `tool_calls`.

## request_flow
1. `POST /v1/chat/completions` arrives at `proxy/app/router.py`.
2. Validates the `model` request against `proxy/app/models.py`.
3. Checks if standard conversational mode or tool-enabled `agent_mode` is requested (`is_pi_agent_request` in `tools_shim.py`).
4. Compiles the message history into a synthesized prompt for the underlying ChatGPT web client.
5. In `proxy/app/client.py`, the proxy requests a transport layer (`build_transport`) to send the message payload.
6. The underlying `playwright` transport connects to the local Chromium browser (via CDP or Persistent Context) and sends the message.
7. The streaming response from ChatGPT is caught by `proxy/app/streaming.py`.
8. The raw ChatGPT text stream is parsed and chunked into `StreamChunk` SSE events and forwarded to the client.
9. If in `agent_mode`, the response is intercepted, checked for tool formatting (`<tool_call>...</tool_call>`), and transformed into a formal OpenAI `finish_reason: "tool_calls"` response.

## notable_modules
### proxy/app/config.py
- Parses `CHATGPT_PROXY_*` environment variables.
- Supplies critical automated browser path resolution (consuming `wrapper/paths.py` to identify the downloaded Playwright Chromium binary).
- Configures port, host, headless state, debugging ports, and the local `browser_profile` path.

### proxy/app/router.py
- Implements FastAPI HTTP routes.
- Contains the `resolve_agent_action` loop which intercepts malformed tool calls and automatically injects a `build_tool_repair_prompt` to force ChatGPT to fix its own syntax errors.

### proxy/app/tools_shim.py
- Defines the translation layer for function calling.
- Contains `PI_TOOL_NAMES` mappings.
- Reads `<tool_call>` and `<write_content>` XML-like blocks generated by ChatGPT and translates them into `action.kind = "tool"`.

### proxy/app/state.py
- A simple in-memory session store.
- Maps `conversation_id`s to active `ChatTransport` instances so contextual chats maintain history without restarting the browser transport.

### proxy/app/streaming.py
- Implements the `sse()` and `done_sse()` logic to accurately mimic OpenAI's HTTP chunked transfer boundaries.

## implementation_characteristics
- Tightly couples with the `pi` coding agent logic to ensure developer roles and specific tool formats are handled seamlessly.
- Prefers `playwright` transport over pure `requests`/`curl_cffi` because of complex bot-mitigation mechanisms introduced by OpenAI (Turnstile, Arkose, etc.).
- Maintains complete state isolation inside `data/browser_profile` to prevent pollution of user data.

## coding_rules
- JavaScript execution is Bun-only.
- Do not use `npm`, `node`, `npx`, `yarn`, or `pnpm` in new scripts, CI steps, docs, or test commands.
- Use `bun run ...`, `bun test ...`, or direct `bun <file>.mjs` invocations instead.
- Fast CI should remain live-service-independent; browser E2E stays opt-in.
- See `docs/writing_rules.md` for the strict repository-wide rule set.

## caution
- Port binding issues: It is explicitly bound to `0.0.0.0:8081` or `127.0.0.1:8081` to avoid common macOS conflicts (e.g. `spoofdpi` on port `8080`).
- Browser limitations: The underlying Playwright Chromium instance depends strictly on correct command-line flags (`--no-sandbox`, `--disable-gpu`, `--single-process`, `--password-store=basic`) to bypass macOS Sequoia constraints and Gatekeeper termination.
